# 小鸟过管道 · DQN 强化学习 AI

> 用强化学习让 AI 自己学会玩微信小游戏《小鸟过管道》（Flappy Bird 加强版）。
> **不修改一行游戏代码**——直接把原版 `main.js` 装进 Node 沙箱当作参考环境，
> 用 numpy 向量化环境 + Dueling Double DQN + 优先经验回放训练，
> 并且用逐帧对拍证明「AI 训练的环境 ≡ 真机游戏逻辑」（48572 帧逐位相同）。
>
> 关键词：`PyTorch` `DQN` `PER` `n-step` `势函数奖励塑形(PBRS)` `向量化环境` `Node vm 无头复用 JS 游戏`

想直接看它玩？装好依赖后一条命令（`./play.sh` 会自动使用项目里的 venv）：

```bash

```

## 二、最硬核的一点：环境和真机游戏**逐位一致**

强化学习项目最容易自欺欺人的地方是「自己写了一个像 Flappy Bird 的东西」然后宣称学会了玩游戏。
本项目的做法是：

1. `tools/ref_env.js` 用 Node 的 `vm` 沙箱 **原封不动** 载入游戏的 `js/main.js`（只 stub 掉 `wx.*` 图形/音频 API），
   直接调用游戏内部的 `reset()` / `upd(dt)`，得到逐帧的完整游戏状态；
2. `dqn_bird.py` 里的 `ScalarBirdEnv` 是同一份逻辑的 Python 移植（连**粒子系统消耗随机数**这种细节都保留，
   因为它会影响后续管道生成）；
3. 两端使用**同一套种子化 PRNG**（mulberry32，双方逐位同流），吃同一份动作序列；
4. `tools/parity_test.py` 逐帧比对：鸟的位置/速度、分数、等级、命数、五种管道连击计数、连击计时、
   每根管道的位置/间隙/类型/是否已计分、**随机数流内部状态**、甚至**存活粒子数**。

实测结果（覆盖 3 只鸟 × 不同星级 × 翅膀装备共 6 种玩法配置）：

```

## 三、游戏机制（环境复刻的对象）

原版 `js/main.js` 的核心规则：

| 项 | 值 |
|---|---|
| 重力 / 跳跃初速 | `G=1800 px/s²`、`JV=-480 px/s` |
| 管道基础速度 / 宽度 / 间隙 | `180 px/s`、`50`、`150` |
| 管道间距 | `200 px`（红管额外 +75 前移） |
| 出生位置 | 鸟固定 `x=100`，`y=300`，`30×30` |
| 难度递增 | `level = 通过管道数 / 10` → 管速 `+8×level`，有效间隙 `−min(2×level,16)` |
| 五种管道 | 绿(42%)、红(18%, 1.5倍速)、蓝(18%, 上下摆动±40px)、紫(12%, 间隙×0.8)、金(10%, +3分) |
| 连击 | 同色累计 10 根（小黄3星=8）触发：绿=其他计数+2 / 红=+1命 / 蓝=难度−1 / 紫=下5管间隙翻倍 / 金=下5管得分翻倍 |
| 命数 | 撞管时若 `lives>1` 只扣命并炸掉该管 + 1.5s 无敌，`lives≤1` 撞管或撞顶/撞底才死 |

**难度无上限**：管道速度随分数线性增长，所以「活得越久越难」，高分完全靠策略。

## 四、强化学习建模

### 状态（34 维，全部来自游戏内部量）

```
鸟:      y/600, v/900
最近2根管: Δx/500, (间隙中心−鸟中心)/600, 有效间隙(=gap−gs)/150, 当前管速/600,
           管道类型 one-hot(5), 摆动管相位 sin/cos        → 每根 11 维
全局:    level/20, lives/6, 无敌剩余/1.5, 紫连击剩余/5, 金连击剩余/5
连击进度: 五色计数 min(count, reqC)/reqC（HUD 上本来就显示"10/10"这种进度条）
```

摆动管给了 `sin/cos(相位)`，网络因此能预测蓝管未来位置；管速与 `level` 让网络知道「还剩多少反应时间」。

### 动作
2 个离散动作：`0=不跳`、`1=跳`（等价于触摸屏幕）。60Hz 逐帧决策。

### 奖励

```
r = 本帧真实得分增量×1.0          （金管 +3/+4、金连击 ×2 都按游戏真实计分）
    − 掉一条命 ×1.0
    − 死亡 ×1.0
    + γ·Φ(s′) − Φ(s)              ← 势函数奖励塑形 (PBRS)
```

其中 `Φ(s) = −0.5 · clip(|鸟中心 − 最近管道间隙中心| / 300, 0, 1)`，`Φ(终止态)=0`。

**为什么用 PBRS**：只用稀疏的「过管 +1 / 死亡 −1」时，智能体会退化到「贴地飞行」的局部最优——
因为存活奖励与高度无关，价值函数对高度「无所谓」，加上 ε 探索后鸟在 46 帧内就撞死了，
**永远见不到 90 帧才出现的第一根管道**（这个坑在开发记录里写得很清楚）。
PBRS 是 Ng et al. 1999 的经典结论：**塑形后的最优策略与原奖励完全一致**，
只是把「靠近间隙中心」这个密集信号教给网络。实测塑形系数不能太大（w=2/4 反而更差，会淹没真实奖励）。

### 算法

**Dueling Double DQN + 3-step 回报 + 优先经验回放(PER, α=0.6, β 0.4→1) + Huber loss + 硬更新目标网络**

| 超参 | 值 |
|---|---|
| 网络 | MLP 34→256→256→(V:A) 双头 Dueling |
| 优化器 | Adam, lr 2.5e-4（续训微调 5e-5） |
| 折扣 / n-step | γ=0.99 / n=3 |
| 回放池 / batch | 300,000 / 256 |
| 并行环境 | 256 只鸟同时跑，各自独立随机流，死亡即自动开新局 |
| 更新比 (UTD) | 每个 tick 64 次梯度更新（= 每 4 个环境步 1 次） |
| 探索 | ε: 1.0 → 0.05（线性 250k 步），续训 0.05 → 0.02 |
| 训练量 | 阶段1 从零 2M 步 + 阶段2 续训 6M 步，单张 RTX 5060 Laptop（合计约 55 分钟） |
| 环境吞吐 | 向量化环境 1.6M 鸟步/秒（N=512，单进程 numpy）；原版 JS 参考环境 8M 步/秒 |


### 训练过程（两阶段）

| 阶段 | 步数 | 说明 | 贪心评估均分 |
|---|---|---|---|
| 阶段1 从零训练 | 0 → 2.0M | lr 2.5e-4，PER，ε 1.0→0.05 | 0 → **5.60** |
| 阶段2 续训 | 2.0M → 8.0M | 载入阶段1最优，lr 5e-5，ε 0.05→0.02 | 5.28 → 10.5 → 17.5 → 24.7 → **32.18** |

阶段2 的关键是**先灌满 30 万条经验再开始学习**（`--learning-starts 300000`）：
一开始直接用 2 万条的小回放池续训，两万次梯度更新就把 5.60 的策略打回 1.16；
改成“灌满 + 降 lr”后，同样的权重在半小时内一路涨到 32 分。

最终模型 200 局评估明细：均值 30.77、中位 30、最高 65、
P90 44.0、最低 6、标准差 10.34、平均存活 1821 帧（≈30 秒）。

### 消融实验：组件与回放策略

统一设置（从零训练、相同随机种子、相同奖励、700k 步、40 局贪心评估）：

| 配置 | 700k 步评估均分 | 说明 |
|---|---|---|
| Vanilla DQN（uniform 回放） | **9.30** | 无 Double / 无 Dueling |
| + Double DQN | 7.80 | |
| + Double + Dueling | 7.62 | |
| + Double + Dueling + **PER** | 1.27 | 明显落后 |

三个 uniform 变体互相之间在噪声范围内（7.6~9.3），**但 PER 在训练前期显著拖慢学习**。
原因不复杂：前期回放池小、策略变化快，PER 按 TD 误差采样会把绝大多数样本集中到
"刚死亡"的那批转移上，数据多样性骤降；同时重要性采样权重（实测均值 ≈0.44）
等价于把有效学习率又压掉一半。

> 有意思的是：我们最终的主模型（32.18 分）恰好是用 PER 训出来的——PER 在**后期**（回放池灌满、
> 策略稳定后）才发挥作用。如果重训，建议前期 uniform、后期再切 PER。
>
> 另外补一句实话：**DQN 的种子方差很大**。我们用同一套配置换种子重跑，有的 50 万步就卡在 0 分
> （鸟连第一根管子都见不到），有的 60 万步就到 9.3 分。仓库里给出的 32 分模型是跑通的那一条轨迹；
> 想复现出同等分数，建议多开几个种子挑最好的。

## 五、复现步骤

```bash
# 0) 环境（需要 Python 3.12+ 与 Node.js 18+；没有 uv 就用 python3 -m venv）
uv venv --python 3.12 .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt # 或用 pip install -r requirements.txt

# 1) 自检：PRNG 与 JS 逐位一致 + 两个环境互相一致
python dqn_bird.py self-test          # 激活 venv 后 python 才指向 .venv

# 2) 保真验证：与原始游戏逻辑逐帧对拍
python dqn_bird.py parity --episodes 12

# 3) 环境吞吐
python dqn_bird.py bench --n-envs 512

# 4) 基线
python dqn_bird.py baselines --episodes 100

# 5) 训练（GPU；CPU 也能跑，加 --device cpu。仓库里已带训好的 runs/main/best.pt）
python dqn_bird.py train --steps 2000000 --n-envs 256 --updates-per-step 64 \
       --lr 2.5e-4 --out runs/my_run

# 6) 评估 + 画曲线 + 录 GIF（用仓库自带的权重）
python dqn_bird.py eval --ckpt runs/main/best.pt --episodes 200
python dqn_bird.py plot --csv runs/main/log.csv runs/lr25/log.csv --out docs/training_curve.png
./play.sh --out docs/ai_play.gif --max-seconds 20
```

> 如果上面前提是「没激活 venv」，把命令里的 `python` 换成 `.venv/bin/python` 即可，例如
> `.venv/bin/python dqn_bird.py eval --ckpt runs/main/best.pt --episodes 200`。

## 七、开发记录：踩过的坑（这部分比结果更有信息量）

1. **死亡惩罚写成了死亡奖励**：`reward += death * dead` 而不是 `− death * dead`。
   结果智能体学会了「以最快速度撞天花板自杀」——41 帧必死、永远拿 0 分，而且价值函数拟合得**非常准**
   （Q 与蒙特卡洛回报几乎完全吻合），只是奖励本身是错的。定位方法：拿实际回报和 Q 值逐帧对比。
2. **稀疏奖励下的「贴地飞行」局部最优**：见第四节，靠 PBRS 解决。
3. **只对拍分数是不够的**：一开始只比对 `score/pipes`，前 1700 帧都对，之后才发散。
   给两端加上**随机数流内部状态**和**粒子数**的逐帧比对后，立刻定位到两处移植遗漏：
   连击触发时的粒子特效（12/15 颗）以及掉命时「20×0.6 + 10×0.5」的两次粒子调用被合并成了一次
   （粒子数会影响 `PTCN` 上限判断，进而影响后续随机数消耗 → 管道序列漂移）。
4. **续训不稳**：直接在小回放池上以高 UTD 继续训练，2 万次更新就把 5.60 的策略打回 1.16。
   改成「先灌满 30 万条经验再开始学习 + 学习率降到 5e-5」后，同样的权重续训到 10.5 分。

## 八、局限与后续

- **分数还没超过手写启发式（30.8 vs 54.6）**。差距主要在后期：启发式平均活 2903 帧，
  DQN 平均活 1821 帧，说明它在高等级（管道更快、间隙更窄）下控制精度还不够。
  可继续从 `runs/main/best.pt` 续训，但注意第七节的"续训不稳"——务必用 `--learning-starts ≥ 回放池容量`
  且把学习率降到 5e-5 量级，否则两万次更新就能把 32 分的策略打回 0 分（我们踩过两次）。
- 目前只训练 **小黄·1星（新手配置）**。游戏里还有 小粉3星（绿管变金管 + 50% 闪避，得分上限最高）、
  小黄3星（5 命 + 连击门槛 8）等配置，以及火箭背包技能（可扩成第 3 个动作），
  用 `--bird/--stars/--wings` 就能直接开训。
- 环境是 60Hz 定步长，真机是 `requestAnimationFrame` 变步长；变步长下物理会有毫秒级差异。
```
